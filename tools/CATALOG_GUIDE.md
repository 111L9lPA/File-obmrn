# Как добавить программу так, чтобы она появилась в библиотеке

1. Сохранить новый .nc в корне репозитория под новым именем. Проверить нужные координаты/режимы отдельно от сайта. Не менять прежний файл.
2. Опубликовать файл и получить SHA коммита. Вычислить SHA-256 именно байтов, размер в байтах. Ссылку использовать вида https://raw.githubusercontent.com/111L9lPA/File-obmrn/<полный-коммит>/<файл.nc>.
3. Добавить/обновить проект в docs/catalog.json. Формат описан в docs/catalog.schema.json. Схемы и фотографии класть в docs/assets/. У каждого изображения также SHA-256. Русские названия допустимы в JSON; NC не переписывается.
4. Запись операции: id, понятный title, filename, url, sha256, bytes, tool, depth (положительная величина в мм от нуля, пояснить ноль), order, version, archived, rpm, feeds, requires, note, source, revision (SHA коммита). Неизвестные параметры — null/пустой список, не выдумывать.
5. Сведения о заготовке X/Y/Z — stock, готовые детали — parts, нули — zero. Если версии отличаются заготовкой, писать это в note старой операции. Проект показывает текущую заготовку. Для отдельной подборки проб указать sequence:false.
6. cutStatus: not_reported / partial_reported / reported. Источник и объём подтверждения описать в note. checkStatus: geometry_checked только при фактической проверке; иначе not_reviewed. Это не гарантия безопасности. Местные отчёты пользователя в браузере привязаны к sha256 и не публикуются автоматически.
7. Не удалять прошлые операции: пометить archived:true. Порядок задаётся order (40→42→41), requires содержит id необходимых предшествующих операций. Сайт не разрешает и не запускает станок.
8. Увеличить revision и updatedAt каталога. Проверить хеши файлов и связи изображений. Выполнить node --test tests/core.test.js, python tools/package_site.py. При изменении интерфейса выполнить browser QA.
9. Закоммитить каталог, изображения и новый sw.js/portable-template.json. Сайт увидит обновление после кнопки «Обновить» с подтверждением. NC без записи найдёт как «Неразобранные»; это запасной путь, не замена описанию.

build_catalog.py — однократное восстановление первоначального каталога по контексту этой сессии. Не запускать поверх последующих ручных дополнений: он пересоздаёт каталог и требует исходных файлов из workspace.
